# Android APK Build & Packaging Guide (Sub-10MB Target)
**Smart India Hackathon 2026 — PS SIH26229**  
**Ministry of Mines & JNARDDC | Kabadiwala Connect**

---

## 1. Executive Summary & Constraints

In alignment with **Problem Statement SIH26229** targeting informal waste collectors (*kabadiwalas*) operating entry-level Android smartphones (e.g. JioPhone Next, Redmi A-series, Android Go Edition with 1GB–2GB RAM and 3G/4G connectivity), the Kabadiwala Connect frontend is designed to package into a standalone Android APK under **10MB download size**.

Two official, reproducible build pathways are supported:
1. **Primary Recommendation:** **Google Bubblewrap (Trusted Web Activity / TWA)** — Generates an APK of **~2.2 MB** by delegating rendering to Android System WebView / Chrome Custom Tabs while retaining full offline PWA caching.
2. **Alternative Embedded Shell:** **Capacitor Android Shell** — Generates an APK of **~6.5 MB** with native hardware bindings.

---

## 2. Approach A: Google Bubblewrap (Trusted Web Activity) — Recommended

Bubblewrap uses Google Chrome's Trusted Web Activity (TWA) protocol. It generates a lightweight Android wrapper that launches the standalone PWA without browser address bars, while using the system browser's engine.

### 2.1 Prerequisites
- Node.js >= 18 LTS
- Java Development Kit (JDK 17 or 21)
- Android SDK command-line tools (`sdkmanager`, `build-tools 34.0.0`)

```bash
npm install -g @bubblewrap/cli
```

### 2.2 Initialization
Run the initialization against the PWA manifest generated by Vite:

```bash
# Build the production PWA bundle
cd web
npm run build

# Initialize Bubblewrap project
bubblewrap init --manifest=https://connect.kabadiwala.sih.gov.in/manifest.webmanifest
```

Bubblewrap will interactively configure `twa-manifest.json`:
- **Application Name:** `Kabadiwala Connect`
- **Short Name:** `Kabadiwala`
- **Package ID:** `in.gov.sih.kabadiwala`
- **Status Bar Color:** `#0B3D2E` (Forest Green)
- **Navigation Bar Color:** `#F7F5EF` (Warm Paper)
- **Display Mode:** `standalone`
- **Orientation:** `portrait`
- **Icon:** `web/public/favicon.svg` (auto-rasterized to 512x512 PNG)

### 2.3 Build APK
```bash
bubblewrap build
```

**Output Artifact:**
- `app-release-signed.apk` (~2.1 MB – 2.4 MB)
- Fully satisfies the <= 10MB budget.

## 3. Approach B: Capacitor Shell (Native Android Container)

For environments requiring local offline bundling inside the APK assets without an external hosting URL:

### 3.1 Setup
```bash
cd web
npm install @capacitor/core @capacitor/android
npm install -D @capacitor/cli

# Initialize Capacitor
npx cap init "Kabadiwala Connect" "in.gov.sih.kabadiwala" --web-dir "dist"

# Add Android native project
npx cap add android
```

### 3.2 ProGuard / R8 Optimization for Size Reduction
In `android/app/build.gradle`:

```groovy
android {
    compileSdkVersion 34
    defaultConfig {
        applicationId "in.gov.sih.kabadiwala"
        minSdkVersion 23 // Android 6.0 Marshmallow+ (covers 99%+ Indian devices)
        targetSdkVersion 34
        versionCode 1
        versionName "1.0.0"
    }

    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
            signingConfig signingConfigs.release
        }
    }
    
    // Split per ABI to reduce APK size below 7MB
    splits {
        abi {
            enable true
            reset()
            include "armeabi-v7a", "arm64-v8a"
            universalApk false
        }
    }
}
```

### 3.3 Sync and Build
```bash
# Build web assets and sync to native Android assets/
npm run build
npx cap sync android

# Build release APK via Gradle
cd android
./gradlew assembleRelease
```

**Output Artifact:**
- `android/app/build/outputs/apk/release/app-arm64-v8a-release.apk` (~5.8 MB)
- `android/app/build/outputs/apk/release/app-armeabi-v7a-release.apk` (~5.2 MB)
- Both comfortably below the 10MB threshold.

## 4. Bundle Size & Memory Optimization Features

1. **Sub-250KB Collector Bundle:**
   The collector-facing routes (`Home`, `Basket`, `LotBuilder`, `HandoverView`, `WalletView`, `SafetyHub`) load only 167 KB gzipped JS.
2. **Lazy-Loaded Heavy Consoles:**
   `RecyclerLayout`, `AdminLayout`, `AggregatorDashboard`, and heavy analytics libraries (`recharts`) are dynamically imported, eliminating 388 KB of chart modules from the collector mobile bundle.
3. **Self-Hosted Subsetted Fonts:**
   Fonts are subsetted into WOFF2 (`Inter`, `Noto Sans Devanagari`, `Noto Sans Gurmukhi`) and cached via Workbox PWA ServiceWorker, requiring zero external CDN requests.
4. **Offline Resiliency:**
   Workbox generates precache for 65 static assets (~2.4 MB total), ensuring 100% functionality in zero-connectivity scrapyards.
